# Как появляются новые котики

Слово «котик» в PetCrew может означать две разные вещи:

1. **агента в стае** — новую задачу или субагента с собственной карточкой;
2. **визуального питомца** — персонажа в левой части Monitor.

Новые агенты уже поддерживаются. Несколько сменяемых визуальных питомцев — пока
нет. Ниже эти сценарии разделены намеренно.

## Добавить ещё одного агента

Вручную создавать карточку в PetCrew не нужно.

1. Подключите адаптер нужного провайдера.
2. Запустите новую задачу или субагента обычным способом в Codex/OpenCode.
3. Адаптер передаст стартовое событие в Core.
4. PetCrew создаст или обновит карточку по стабильной технической идентичности.

Субагент получает ссылку на родителя через `parent_agent_id`. Поэтому действие
`Прочитать субагентов` может отличить дочерние результаты от корневых задач.

Если один разговор провайдера содержит несколько последовательных ходов,
адаптер обязан различать их. Завершённый ход не должен случайно оживать от
старого события.

## Добавить задачи из другого проекта

Отдельной регистрации проекта нет. После установки глобального адаптера новая
задача из другого проекта появляется автоматически.

PetCrew хранит и показывает только безопасное короткое имя проекта. Полный путь
не входит в обычное состояние и кеш. Провайдер может отдельно дать временную
навигационную цель для явного клика по карточке; она не должна сохраняться в
долговременном кеше.

## Подключить Codex

Исходник плагина находится в `plugins/petcrew/`, а описание локального
marketplace — в `.agents/plugins/marketplace.json`.

Подключение выполняется через поддерживаемую поверхность Plugins текущей версии
Codex:

1. проверить тесты, манифест и хеши хуков;
2. сделать резервную копию существующей конфигурации;
3. установить `petcrew@personal` штатным способом;
4. отдельно просмотреть и доверить точные команды хуков;
5. начать новую тестовую задачу и проверить полный жизненный цикл карточки.

Нельзя вручную править установленный кеш, заменять существующий `notify`,
обходить доверие хуков или ставить второй Python ради PetCrew. Точная процедура
и откат описаны в [INSTALLATION.md](INSTALLATION.md).

## Подключить OpenCode

Адаптер находится в `adapters/opencode/petcrew.js`. В репозитории он инертен и
сам не устанавливается.

Перед активацией:

1. выполнить `node --test adapters/opencode/petcrew.test.mjs`;
2. проверить текущий аудит и контракт обработки данных;
3. сохранить существующий целевой файл, если он есть;
4. показать точный путь копирования и необходимость перезапуска;
5. после явного разрешения установить адаптер штатным способом OpenCode;
6. проверить одну новую задачу и одно завершение без дублей.

## Подключить третий провайдер

Пользовательской кнопки «Добавить сервис» пока нет. Новый провайдер требует
разработки адаптера:

```text
события провайдера
        ↓
адаптер adapters/<provider>/
        ↓ protocol 1.0
PetCrew Core
        ↓
общий UI без провайдер-специфичной логики
```

Адаптер должен:

- создавать непрозрачные идентификаторы до отправки события;
- передавать только разрешённую семантику;
- не читать промпты, сообщения, содержимое вызовов инструментов, учётные
  данные и приватные базы;
- отличать корневые задачи, субагентов и последовательные ходы;
- подтверждать терминальное событие, а не угадывать его по бездействию;
- иметь изолированные тесты и отдельный план установки/отката.

Полный разработческий чеклист: [NEW_PROVIDER_INTEGRATION.md](NEW_PROVIDER_INTEGRATION.md).

## Добавить другого визуального котика

В текущей версии это **не поддерживаемая настройка**. В Monitor встроена одна
CSS-фигура питомца, которая меняет настроение по агрегированному состоянию
команды. Формата набора питомца, каталога ресурсов, выбора персонажа и
безопасной
процедуры установки пока нет.

Поэтому сейчас не следует копировать изображения в приложение или заменять
установленные pet assets вручную: это будет локальный неподдерживаемый патч.

Чтобы сделать визуальных котиков настоящим расширением, отдельно понадобятся:

- версия формата набора питомца;
- манифест с именем, автором, лицензией и совместимостью;
- обязательные состояния, ресурсы и запасной вариант;
- локальная валидация путей и размеров;
- выбор и предпросмотр в UI;
- установка без изменения бинарников приложения;
- откат к встроенному питомцу.

До появления такого контракта «дополнительный котик» в пользовательской
документации означает нового агента с карточкой, а не новый визуальный скин.
